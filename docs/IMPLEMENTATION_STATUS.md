# 26 августа 2026 — Messenger: идемпотентный read receipt

Устранён цикл запросов `messages → read → realtime invalidate → messages`: эффект пометки прочитанным теперь хранит последний отправленный `messageId` отдельно для каждого conversation и не повторяет запрос для уже отмеченного сообщения. Новый входящий message по-прежнему получает read receipt, но один и тот же ответ истории больше не создаёт бесконечный refetch.

# 26 августа 2026 — Messenger: стабильное воспроизведение media

Причина остановки голосового сообщения была во frontend: событие `message.read` инвалидирует messenger-cache, а новый ответ backend содержит новый presigned `downloadUrl`. Из-за смены `src` нативный audio-элемент пересоздавал буфер и прекращал воспроизведение.

Добавлен изолированный `MessageAttachment`: он сохраняет URL вложения по ключу `mediaId` и не меняет `src` при очередном обновлении RTK Query. При реальной ошибке загрузки используется только более свежий URL из ответа. Это стабилизирует audio, video и image-preview, устраняет мерцание и не отключает read receipts/realtime обновления.

Отступ `pb-24`, ранее добавлявшийся на страницах под нижний dock, удалён: прокрутка теперь не содержит искусственного нижнего пространства.

Нижнее меню теперь можно масштабировать по высоте: справа добавлен вертикальный доступный ползунок, работают также стрелки клавиатуры, диапазон ограничен 44–180 px, выбранный размер сохраняется в localStorage. Размер иконок, hover magnification и подъём иконок масштабируются вместе с dock в стиле macOS.

Для маршрутов раздела «Моя семья» добавлен переиспользуемый `PageLayout` в `shared/ui`: он задаёт единый scroll-контейнер, ширину и базовый межблочный отступ. В `@theme` добавлены токены `--spacing-block` (5px), `--text-body` (18px) и `--text-heading` (24px).

Добавлены токены `--spacing-gap` и `--spacing-page`: базовый gap теперь 5px, padding авторизованного page-контейнера — 10px через `MainLayout`.

Все классы `gap-*` в TSX-контейнерах заменены на единый `gap-gap` (5px), включая адаптивные `gap-x/gap-y`, чтобы межэлементные интервалы задавались одним токеном.

Ограничения `max-w-*` удалены из страниц, route-layout и общих контейнеров: основные экраны теперь растягиваются на всю доступную ширину.

Выпадающий список `Select` перенесён в `document.body` через React Portal. Позиция меню вычисляется относительно триггера и обновляется при resize/scroll, поэтому список отображается поверх карточек, overflow-контейнеров и stacking contexts.

Рендер портального списка упрощён: он больше не зависит от `AnimatePresence`-обёртки, которая могла препятствовать отображению portal-узла. Меню монтируется напрямую при открытии.

На странице задач форма создания/редактирования и список задач размещены в двух колонках 60/40. В элементах списка название, срок и исполнитель выстроены в одну строку с компактной адаптивной сеткой.

Структурные CSS-селекторы для sticky-заголовков удалены. Route-level заголовки используют явный класс `.page-header`, что исключает зависимость от вложенности DOM и упрощает поддержку новых страниц.

Проведён первый код-аудит по frontend best practices: убрана небезопасная цепочка `as unknown as` в календаре задач, добавлен runtime type guard для неизвестного task response, исправлены дублирующиеся `gap-gap`, а перегруженная разметка Sidebar отформатирована для читаемости. `generated/api.ts` не изменялся.

Нормализация неизвестного ответа задач вынесена из виджета календаря в `entities/task` (`getCalendarTasks` и `CalendarTask`), чтобы API-shape parsing не смешивался с UI-логикой и мог переиспользоваться другими потребителями.

В ходе продолжения аудита исправлены оставшиеся дробные интервалы `gap-2.5`, которые ранее были ошибочно затронуты механической заменой базовых gap-классов; базовый `gap-gap` применяется только к одноуровневым контейнерам.

Исправлен scroll на `/my_family/calendar` для узких экранов: страница календаря снова использует собственный `overflow-auto`, контентный контейнер имеет `min-h-full`, а внутренний widget больше не ограничивается `h-full` и устаревшим нижним padding.

Базовый `Button` теперь сам задаёт `inline-flex`, `items-center`, `justify-center` и `leading-none`. Иконки и текст в кнопках выровнены по общей вертикальной оси, поэтому локальные обёртки кнопок больше не дают визуального смещения иконок вверх.

## Принятые решения

- Семья целевой модели: два взрослых партнёра и их дети; расширенные родственники — только календарные записи/контакты.
- Wellbeing private-by-default: никаких диагнозов, скрытого анализа партнёра, рейтингов или слежения.
- API-контракт проверяется на backend до frontend-реализации; generated RTK Query code вручную не редактируется.
- Для frontend-задач backend read-only: агент только сверяет контракты и останавливает срез при недостающем backend API.
- Основной рекомендуемый family onboarding — закрытое приглашение знакомого партнёра; публичный каталог пока остаётся существующей функцией и будет пересмотрен отдельным срезом.
- Текущий закрытый onboarding использует передаваемую партнёру одноразовую ссылку, привязанную к точному email; автоматическая email-доставка находится вне frontend-плана.
- Browser QA, backend e2e, notification outbox/scheduled jobs и production readiness вынесены из frontend-плана; эти задачи ведёт пользователь отдельно.

## Известные пробелы

- Backend-сверка 16.08.2026: текущие стабильные финансовые frontend-контракты ограничены wallet API (`POST/GET/PATCH/DELETE /families/me/wallets`). В backend-документации заявлен следующий срез idempotent ledger-команд, однако в фактическом `src/modules/finance` пока присутствуют только wallet controller/service/DTO; endpoints income/expense/transfer и response DTO ещё не опубликованы. Финансовый UI поэтому не начинаем до появления и проверки этих контрактов. Следующим безопасным срезом остаётся lifecycle/visibility audit и UI primitives, не требующий новых backend endpoint.
- Для family lifecycle добавлена панель подтверждённых backend-команд: выход из семьи, архивация и восстановление. Она использует существующие generated RTK Query hooks, показывает ошибки API и явно объясняет сохранение shared data; команды dissolution и visibility-grants не выведены до отдельного UX-аудита и появления потребителя чувствительных данных.

- `MainPage` уже содержит первую встречу, семейные задачи и календарь, но пока не собран в целевой cockpit «сегодня / неделя / нужно решение».
- Family events пока не поддерживают recurrence, reminders, all-day и участников; текущий календарь работает с одиночными событиями и максимум 100 записями на видимый диапазон.
- Автоматических frontend-тестов пока нет.
- Shopping endpoints опубликованы без response DTO в Swagger, поэтому generated RTK Query возвращает `unknown`; frontend временно повторяет backend response DTO в `entities/shopping`.
- Notification inbox опубликован без response DTO, а preferences отсутствуют в текущем generated API; frontend временно отражает фактические backend DTO в `entities/notification` и подключает существующие preferences endpoints через RTK Query injection.
- Расширенный task MVP заблокирован отсутствующими backend-моделями и API для checklist items, postpone/reschedule с причиной, effort/mental-load, ротации исполнителей и недельной субъективной оценки справедливости. `assignedToId` уже поддерживается и подключён на frontend; «свободная задача» представлена `null`.
- В браузерной проверке гостевых маршрутов обнаружен отсутствующий `/favicon.ico` (404); на функциональность страниц не влияет.
- Адаптивность панели безопасности исправлена: внутренние формы больше не переполняют узкий экран, а подтверждение email складывается в колонку на мобильной ширине. В меню для раскрытых разделов добавлено видимое название родительского блока.
- Исправлено обрезание hover-shadow у панелей главной страницы: scroll-колонки получили внутренний отступ, чтобы внешнее свечение не упиралось в границы overflow-контейнера.
- Блоки страницы `my_family` переведены на общий `shared/ui/AnimatedPanel`, включая карточки участников и состояние отсутствующей семьи; дублирующие стили контейнеров удалены.
- Проведён аудит повторяющихся page/feature-контейнеров: профиль, безопасность, family activity, invitations и private invitations переведены на `AnimatedPanel`; специализированные calendar/table/inner-state блоки оставлены без замены из-за собственного overflow/layout.
- Маршруты переведены на route-level code splitting через `React.lazy`/`Suspense`; общий fallback загрузки вынесен в `shared/ui/route-loading`. Стартовый JS entry уменьшен с 855 КБ до 205 КБ (gzip с 264 до 66 КБ), страницы собираются отдельными чанками. Дополнительные дубли UI-контейнеров не выносились без подтверждённой повторяемости, чтобы не создавать преждевременные абстракции.
- Дополнительно лениво загружаются `RouteTransition`, `MainRouteLayout` и `AppBackground`: общий UI-чанк уменьшен с 351 КБ до 125 КБ, React/animation зависимости вынесены в отдельные кешируемые чанки. Поведение гостевых и защищённых маршрутов сохранено.
